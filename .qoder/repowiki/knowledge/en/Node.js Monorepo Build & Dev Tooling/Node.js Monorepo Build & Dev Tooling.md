The project is a Node.js/React monorepo with no containerization, CI pipeline, or Makefile. Build and lifecycle management are handled entirely through npm scripts and per-package tooling.

**Backend (Express + whatsapp-web.js)**
- Entry point: `backend/src/server.js`, declared as the package main.
- Scripts in `backend/package.json`:
  - `start`: runs the server directly with `node src/server.js`.
  - `dev`: hot-reloads via `nodemon src/server.js`.
  - `setup`, `check-ports`, `smoke-test`, `seed-rooms`, `test-ai`: one-off utility scripts under `backend/src/scripts/` invoked from npm.
- Development reload config: `backend/nodemon.json` watches `src/**/*.{js,json}` while ignoring `node_modules`, `sessions`, `logs`, `.wwebjs_cache`, `.wwebjs_auth`.
- Production process manager: `backend/ecosystem.config.js` (PM2) defines a single-instance app named `nandibaag-backend`, auto-restart on crash/memory limit (`500M`), error/output logs to `./logs/error.log` and `./logs/combined.log`, and sets `NODE_ENV=production`.
- No Dockerfile, docker-compose, Makefile, or GitHub Actions workflow exists in the repo.

**Frontend (Vite + React + Tailwind)**
- Scripts in `frontend/package.json`:
  - `dev`: `vite` (dev server defaults to port 7001).
  - `build`: `vite build` — produces static assets for deployment.
  - `preview`: `vite preview` — serves the production build locally.
- Vite configuration (`frontend/vite.config.js`) adds Tailwind, React, and PWA support; dev proxy forwards `/api` to `http://localhost:7000` (the backend). Icons are generated by `frontend/generate-icons.cjs`.
- No separate frontend build pipeline beyond Vite's built-in bundler.

**Environment & Configuration**
- Both sides use dotenv (`dotenv` dependency); each package ships an `.env.example` alongside its own `.env`. There is no shared env loader or centralized secrets management.
- Backend environment variables are initialized via the `npm run setup` script (`backend/src/scripts/setupEnv.js`).

**Conventions & Gaps**
- Versioning: both packages hardcode `"version": "1.0.0"` in their `package.json`; there is no automated version bumping or changelog generation.
- No cross-compilation, multi-platform builds, or artifact publishing steps are defined.
- No linting, formatting, or test runner scripts are present in either `package.json`.
- Deployment relies on PM2 (via ecosystem config) rather than containers or orchestration manifests.
