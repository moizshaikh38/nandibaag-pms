Two-package monorepo under `nandibaag-bot/`:

- Backend (`backend/src/server.js`, Express + Socket.io) is the single process entry point. It wires security middleware (helmet, cors, compression), rate limiting, morgan dev logging, then mounts REST routes under `/api/{auth,whatsapp,chats,leads,bookings,settings,dashboard,inventory}`. A global error handler sits last. After mounting routes it initializes Socket.io, injects the IO instance into services via `setSocketIo`, connects MongoDB with retry, seeds default admin user and Settings document, restarts any active WhatsApp sessions from `Settings.whatsappNumbers`, starts the follow-up cron, and registers SIGTERM/SIGINT/SIGUSR2 graceful shutdown that destroys all Puppeteer-backed WhatsApp clients.

- Layering inside `src/`: `config/` (env validation via Joi in `env.js`, Mongoose connect, Winston logger) → `models/` (Mongoose schemas exported from `index.js`) → `services/` (business logic: `whatsappService.js` runs multiple `whatsapp-web.js` Client instances keyed by sessionId with LocalAuth persistence under `sessions/<sessionId>/`, per-chat message queue locks, exponential backoff reconnect; `messageHandler.js` orchestrates chat find-or-create, opt-out, mode routing, AI call, lead scoring, follow-up scheduling; `aiService.js` implements a tiered OpenAI-compatible chain — Groq → Cerebras → Cloudflare Workers AI → Gemini → OpenRouter multi-model → hardcoded fallback — plus reply sanitization/validation and an in-memory FAQ cache; `leadScoring.js`, `followUpService.js`, `followUpCron.js`, `systemPrompt.js`) → `routes/` (thin Express routers delegating to services) → `middleware/` (auth JWT guard, error handler, rate limiter) → `sockets/index.js` (Socket.io event wiring).

- Frontend (`frontend/src/App.jsx`, React + Vite + Tailwind v4) renders a protected SPA with `react-router-dom` routes (`/login`, `/`, `/connect`, `/chats/:id`, `/settings`, `/inventory`) wrapped by a `ProtectedRoute` / `ProtectedLayout` that shows a bottom nav. State lives in `context/AuthContext.jsx`; real-time updates come through `hooks/useSocket.js` backed by `utils/socket.js` and `axios` API calls in `utils/api.js`. Pages are split one-per-feature (`Dashboard`, `ConnectPage`, `ChatsPage`, `SettingsPage`, `InventoryPage`).

- Dependency direction: routes → services → models/config; services ↔ sockets (emit events); frontend depends only on backend HTTP + Socket.io endpoints. WhatsApp session state is in-process memory (`Map<sessionId, Client>`) persisted to disk via `LocalAuth` under `backend/sessions/`.
