- Environment variables are declared once in `config/env.js` with a Joi schema and re-exported as camelCase aliases; every required variable has a `.required()` constraint so the server exits at startup if missing.
- Services receive the Socket.io instance lazily via a module-level `setSocketIo(io)` setter called from `server.js`, avoiding circular imports between route/service/socket layers.
- WhatsApp session lifecycle follows a non-blocking pattern: `initSession` registers all `client.on(...)` listeners before calling `client.initialize()`, returns `{ client, initPromise }`, and drives the UI exclusively through emitted events (`whatsapp:qr`, `whatsapp:ready`, `whatsapp:init_failed`, `whatsapp:disconnected`).
- Incoming messages for the same chat phone number are serialized through a per-chat Promise-chain lock stored in `messageQueueLocks`, ensuring sequential processing of Chat document updates.
- AI provider calls share a uniform wrapper (`tryOpenAICompatibleCall`, `tryGeminiCall`, `tryCloudflareCall`) that measures latency, records success/invalid/error counts into an in-memory hourly metrics map, sanitizes output, enforces length limits, and validates replies via `isReplyValid` before returning.
- Frontend pages are organized one file per route under `pages/`, shared UI pieces live in `components/`, cross-cutting concerns (auth state, socket connection) are exposed as React Context or custom hooks rather than inline logic.
